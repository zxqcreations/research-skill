## 快速开始

```
用户：帮我研究[课题名称]，按博士课题标准，覆盖[维度1][维度2]...
```

## 核心特性

| 特性 | 说明 |
|------|------|
| **5阶段流程** | 需求→搜索→撰写→审计→交付 |
| **12维审计** | LaTeX·科学·完整·详实·真实·交叉引用·术语·量纲·数值·文献·自洽·可复现 |
| **对抗验证** | 100+代理Deep Research工作流自动验证关键声明 |

| **可复现性** | 第三方仅凭文档即可复现的严格标准 |

## 审计维度速查

| # | 维度 | 核心检查 |
|:--:|------|------|
| 1 | LaTeX格式 | ≥4轮：脚本批量→手动逐字→grep→最终验证 |
| 2 | 科学性(30%) | 公式推导·概念准确·数值一致·学科共识·内部矛盾 |
| 3 | 完整性(25%) | 章节·参数·边界·文献·代码·竞争对比·失效模式 |
| 4 | 详实性(25%) | 笼统→具体·数据表格化·方法可复现·含完整代码 |
| 5 | 真实性(20%) | 溯源链·外推检测·诚实标注·实验vs仿真区分 |
| 6 | 交叉引用 | 内部链接·编号序列·"详见§X.Y" |
| 7 | 术语一致 | 同一概念同一名称·中英不混用 |
| 8 | 量纲验证 | SI/CGS混用检查·量纲分析·单位换算 |
| 9 | 数值合理 | 数量级检查·典型值对比·上下界检验 |
| 10 | 文献完整 | DOI验证·同行评议确认·一级vs二级来源 |
| 11 | 自洽闭环 | 参数→模型→输出→与文献对比 |
| 12 | 可复现 | 盲测：第三方仅凭文档能否复现？ |

## 评分体系

| 分数 | 等级 |
|:--:|------|
| 9.0+ | 优秀（领域标杆） |
| 8.0-8.9 | 良好 |
| 7.0-7.9 | 合格 |
| 6.0-6.9 | 需显著改进 |
| <6.0 | 不合格 |

综合评分 = 0.30×科学性 + 0.25×完整性 + 0.25×详实性 + 0.20×真实性
（维度1/6-12为修正因子，每个问题扣0.01-0.05分）

## 安装

### 用户级安装（推荐，所有项目可用）

```bash
git clone https://github.com/zxqcreations/research-skill.git ~/.claude/skills/auditable-research
```

### 项目级安装（仅当前项目）

```bash
git clone https://github.com/zxqcreations/research-skill.git .claude/skills/auditable-research
```

安装后重启 Claude Code 会话，skill 将自动被识别。在对话中输入 `/auditable-research` 或描述研究需求即可触发。

### 目录结构要求

```

├── METHODOLOGY.md     # 完整5阶段方法论
├── README.md          # 本文件

    └── master-overview-template.md
```

## 使用

### 触发方式

- **命令触发：** `/auditable-research` 后跟研究课题描述
- **关键词触发：** 提到"博士课题""研究基础设施""系统调研""新领域"等关键词时自动加载

### 使用示例

```
/auditable-research 以[材料]的[器件]为研究对象，按设计原理、工艺、应用、
全球课题组为核心路线，按博士课题标准构建完整研究基础设施。
要求：详细完善、公式完整推导、不图快、不省token。
```

Skill 将自动执行5阶段流程：需求定义→广度搜索→结构化撰写→多维审计→迭代改进→打包交付。

### 配合审计使用

在研究文档撰写完成后，可单独触发审计：

```
请按12维审计策略审计我刚写的文档，输出结构化审计报告和改进优先级。
```
